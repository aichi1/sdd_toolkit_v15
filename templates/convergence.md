# Convergence Log — 収束判定記録

> `/converge` が書き込む記録。**追記専用**。既存のエントリは**変更しない**。
> 訂正・状態変化（`planned` → `deferred` / `dropped` など）が必要な場合も、
> 既存の行を書き換えるのではなく**新しいエントリを追記**する。
> 入力: `/analyze`（`python3 scripts/trace_check.py`。標準出力のみでファイルは作らない）の未完了分類（`planned` / `assigned`）。
> このファイルは `/init-task` または初回の `/converge` が `templates/convergence.md` から作る。

## 0. 記録形式（このセクションは固定。`/converge` はここを変更しない）

各実行で 1 エントリを **§2 の末尾に追記**する。エントリの内部構造は以下で固定する。

### 0.1 エントリの見出し

```
### Entry: <実行日 YYYY-MM-DD> — Phase <NN> / Iteration <N>
```

### 0.2 エントリの本文（この順で書く）

1. メタ情報（3 行固定）
   - `- **入力**: python3 scripts/trace_check.py --markdown の出力（保存した場合はそのパス）`
   - `` - **`trace_check.py` 実行結果**: 要件 <M> 件検査 / 欠陥 <D> 件 / 未完了 <U> 件 ``
   - `- **対象**: このエントリで記録する要件 ID の範囲（例: 「trace-report.md の planned 全件」）`
2. 未達項目の表（**必須の 5 列**。列の順序・見出し文言を変えない）

   ```
   | 要件 ID | 実現フェーズ（docs） | 状態 | 理由 | 持ち越し先 |
   |--------|--------------------|------|------|-----------|
   ```

### 0.3 状態語の語彙（この 3 語に固定。他の語を使わない）

| 状態語 | 意味 | 決定者 |
|--------|------|--------|
| `planned` | 予定どおり未着手。担当フェーズがまだ到達していない | `trace_check.py` の分類をそのまま転記 |
| `deferred` | 担当フェーズを過ぎても未対応で、**先送りをオーナーが決定**した | オーナー決定（日付を理由欄に明記） |
| `dropped` | **対応しないことをオーナーが決定**した | オーナー決定（日付を理由欄に明記） |

> `trace_check.py` が返す `assigned`（宣言済み・未完了）は、**担当フェーズが完了するまでは記録しない**。
> フェーズが完了して `not_delivered`（欠陥）になった場合のみ、オーナー判断を経て `deferred` / `dropped` として追記する。
> `overdue` / `orphan_*` / `phase_mismatch` / `not_delivered` などの**欠陥**分類は `/analyze` の仕事であり、
> 本ログは**欠陥ではないが未達な項目**（`planned` から始まり `deferred` / `dropped` に至りうるもの）を追う。

### 0.4 追記専用の検証コマンド（`/converge` 実行の都度これを実行し、結果を報告する）

```bash
git diff --numstat -- docs/convergence.md
```

**2 列目（削除行）が 0 であること。** 0 でなければ既存のエントリを書き換えている。
**ただしファイルが未追跡（作ったばかりでまだコミットしていない）だと `git diff` は何も出さない。** その場合は
`diff templates/convergence.md docs/convergence.md` を実行し、出力に `<` で始まる行（テンプレートから消えた行）が
無いことを確かめる。

## 1. 用語

- **未達項目**: `docs/requirements.md` の `## 5. 機能要件（R-ID）` の要件のうち、対応する
  `outputs/phase-NN/.metadata.json` の `requirements_addressed` にまだ現れていない要件。
- **持ち越し先**: その項目が次にいつ・どのイテレーション/フェーズで再検討されるか。
  「実現フェーズ」列の値をそのまま使う。オーナー決定で変わった場合はその値を書く。
